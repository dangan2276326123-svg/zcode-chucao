# 画线漏沙采集（2026-11-20）

目的：地里没作物，用**地面画线**模拟芍药带、车带**漏沙**留实际走线，采工程调试用的视频。
**这一路的读数不进论文**（作者 11-13 裁定：调车专用；论文实验只有春测真作物那一处）。
本次规模：20 分钟以内，先小跑，素材不行再补。

## 0. 分工与前提

- 人开遥控器，手不离开遥控 ⇒ 录制必须**开一次、到点自停**，中间不许要人按键。
- 车会走远 ⇒ 录像只能在 X5 本机；网线只用于开录前检查和车回来后的回收，车一动就拔。
- 相机（USB 摄像头）接在 X5 上；开录前先停推流（同一块相机不能两路同占）。

## 1. 开录前（笔记本 → X5）

```sh
# 1) 同步（只拷这两目录；tools/ 在板子上不存在）
scp -r vehicle common sunrise@192.168.127.10:~/qoder/

# 2) 登录 X5，停推流
ssh sunrise@192.168.127.10
pkill -f stream_pi.py

# 3) 一键 demo（批次 t20，20 分钟，每段 120 s）
cd ~/qoder
sh vehicle/collect_demo.sh t20 20
```

`collect_demo.sh` 会先打一屏上板检查（相机节点 / gst / avimux / 占用者 / 剩余盘 / 试录 10 秒的实测码率）：

- **出现 🔴 就停手**，别开录；检查不过就退回"停车 + 网线 + `capture_field` 逐张拍"。
- 检查没 🔴，按回车开录，然后就可以去遥控了。
- 盘的门槛按 **12 MB/s 估算**：20 分钟 ≈ 14 GB，脚本要求剩余 ≥ 计划 × 1.5。12 MB/s 是估的，
  `--probe` 那 10 秒的实测数才是当场凭据。
- 文件名里的日期取 X5 的钟；X5 的钟可能差几小时，要按真实日期落名就把 MMDD 传第 4 个参数：
  `sh vehicle/collect_demo.sh t20 20 120 1120`。

## 2. 采集时的手上规矩

- 开始后**不要碰电脑**；网线可以拔（录像已在后台跑，不跟着 SSH 死）。
- 一段 120 s 自动切段，20 分钟到点自停；**中途断电会丢当前段的索引**。
  要提前停：车接回网线后 `kill -INT <PID>`（脚本打印了 PID），**不要 kill -9**。
- 画线要够长、带弯（S 形、地头转弯），别只跑一条短直线——偏差样本太少。
- 一次只走一种条件；换条件换批次号（t21、t22…），别在同一天同一个批次里混。

## 3. 车回来（笔记本）

```sh
scp -r sunrise@192.168.127.10:~/qoder/data/paint_data/video ./paint_video
```

- 看 `record_log_MMDD.csv`：每段的开始时刻、计划/实际秒数、字节、实测 MB/s、读出的帧数。
- 逐段播一遍：画线在画面里（没过曝/没糊）、没有整段黑帧、段与段接得上。
- 先小跑这一趟的意义就是：**素材没问题再补量**，别一次录满一小时回来才发现画质不对。
